Arshad's Transpose
Circular Linear Algebra on Z₂₅₆

Ring-native transpose, Hilbert-space descent, and BIND · REACT · MEASURE in place of flat signed tensor geometry · September 2026

Abstract

Transpose as Orientation, Not Just Index Swap

Arshad's Transpose is the MPRC proposal for replacing a flat row/column transpose with an operation that preserves circular state, orientation, and ring distance. The unit domain remains Z₂₅₆ with origin/singularity at 128, but learning and descent do not take place inside a single 0–255 unit. They take place over the Hilbert carrier HV×N, where the current visual carrier has HV=14,464 states per sample or layer context.

Critical distinction. Z₂₅₆ is the deterministic state unit. It is not the search space of learning. Descent over 0–255 alone is already closed and deterministic; the computational descent must move over the Hilbert volume HV×N.

01 · Ring Unit

One Unit Is 0…255

The basic state unit is one unsigned byte on the ring:

z ∈ Z₂₅₆
origin / singularity = 128
z < 128 : one side of displacement
z > 128 : opposite side of displacement

The interpretation is geometric: distance from 128 and direction around the ring replace an ordinary signed scalar axis. No float or signed-number representation is required for the core state.

02 · Why Ordinary Transpose Is Incomplete

Matrix Tᵀ Forgets Circular Orientation

A conventional transpose exchanges row and column indices. For an MPRC tensor this is insufficient because the entries also carry ordered ring position and orientation. The transpose therefore has to preserve or explicitly invert the traversal relation; otherwise two tensors with identical rectangular layouts but opposite circular orientation become indistinguishable.

The working principle is:

transpose = index reorientation + ring-orientation transport

This is why the operation is described as circular rather than Cartesian.

03 · Hilbert Volume

Descent Lives in HV × N

For the current vision carrier:

HV = 113 × 128 = 14,464
search domain = HV × N = 14,464 × N

The earlier ADI implementation exposed the important failure mode: navigating descent only over 0–255 confuses the deterministic state alphabet with the computational search space. A byte state already knows how to wrap on Z₂₅₆. What has to be learned is where the interacting state lies across the Hilbert carrier and across N samples, sites, channels, or model states.

05 · Operator Route

BIND · REACT · MEASURE

The learning route uses the GEVHV operator family rather than importing a conventional gradient scale into the ring:

BIND → compose the current state relation
REACT → apply LUT-native activation
MEASURE → compute ring-native discrepancy / target relation

REACT remains a lookup-table operation. MEASURE is the basis for choosing the target or descent direction. The design objective is that the target be read from the measure and finite state domain, rather than created by a hand-tuned floating gradient magnitude.

06 · Measure Before Gradient

Finite Argmin over Ring States

The kernel direction developed with this work treats the target as a finite-state measure problem. For a site with registered states, a candidate displacement v is evaluated directly over the ring:

E(v) = Σ_w Σ_i d_ring(reg[w][i] + v[i], states[w][i])
v* = argmin_v E(v)

Because each local state has only 256 possible ring positions, the local target is finite and directly measurable. The open engineering problem is how to couple those finite local targets across HV×N without collapsing the computational search back into the single-byte domain.

07 · Relation to GEMM/GEMV

From Rectangular Products to Circular Composition

Arshad's Transpose is being developed as part of the broader MPRC kernel route intended to replace or reduce dependence on GEMM, GEMV, IMMA, and conventional gradient descent. The replacement is not claimed merely by renaming matrix multiplication. It requires the same tasks—composition, activation, target selection, and update—to be expressed through ring-native operations and then benchmarked against standard kernels.

The present chapter freezes the geometry and search-space distinction; performance equivalence or superiority remains to be established empirically.

08 · Circular Reversal

Transpose Must Preserve CW/CCW

The quaternion work in Chapter 18 makes the orientation issue explicit: reversing ordered traversal changes the ring orientation by a half-turn in the embedded Q₈ case. Arshad's Transpose generalises the same discipline to tensor state: the transpose cannot silently discard whether a relation was traversed CW or CCW. A valid circular transpose therefore needs an involution test:

T_circ(T_circ(X)) = X

while also preserving ring distance and the intended orientation semantics. The exact kernel law implementing that involution is part of the active proof/implementation work.
